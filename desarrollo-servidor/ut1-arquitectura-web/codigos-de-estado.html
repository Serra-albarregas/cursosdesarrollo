6. Respuestas y códigos de estado

Cada respuesta HTTP comienza con un número de tres cifras que resume qué ha pasado. Es la primera información que leen el cliente, los proxies, los monitores y tú mismo depurando a las dos de la madrugada. Devolver el código correcto es parte del contrato de tu API.

6.1. Las cinco familias​

FamiliaNombreSignificado
1xxInformativaPetición recibida, proceso en curso
2xxÉxitoLa petición se recibió, entendió y aceptó
3xxRedirecciónHace falta una acción adicional
4xxError del clienteLa petición es incorrecta
5xxError del servidorLa petición era válida, pero el servidor falló

📌 La regla que hay que interiorizar: 4xx = "la has liado tú (cliente)"; 5xx = "la he liado yo (servidor)". Devolver un 500 ante datos mal formados del usuario es un error de diseño muy común y hace que tus alertas de producción sean ruido inútil.

6.2. Los códigos que realmente usarás​

2xx — Éxito​

CódigoNombreCuándo
200OKÉxito general con cuerpo de respuesta
201CreatedRecurso creado. Acompañar de Location
202AcceptedAceptado para proceso asíncrono
204No ContentÉxito sin cuerpo (típico de DELETE y PUT)
206Partial ContentRespuesta parcial (Range), descargas y vídeo

3xx — Redirección​

CódigoNombreCuándo
301Moved PermanentlyCambio definitivo de URL; el cliente actualiza marcadores
302FoundRedirección temporal (histórica, ambigua)
303See OtherTras un POST, redirige a un GET. Base del patrón POST/Redirect/GET
304Not ModifiedLa copia en caché sigue siendo válida
307Temporary RedirectComo 302 pero conserva el método
308Permanent RedirectComo 301 pero conserva el método

4xx — Error del cliente​

CódigoNombreCuándo
400Bad RequestSintaxis o validación incorrecta
401UnauthorizedNo autenticado (nombre desafortunado)
403ForbiddenAutenticado pero sin permiso
404Not FoundEl recurso no existe
405Method Not AllowedMétodo no admitido; devolver Allow
406Not AcceptableNo se puede satisfacer el Accept
409ConflictConflicto de estado (duplicado, versión obsoleta)
410GoneExistió y se eliminó definitivamente
415Unsupported Media TypeContent-Type no soportado
422Unprocessable ContentSintaxis válida, semántica incorrecta
429Too Many RequestsLímite de peticiones superado; devolver Retry-After

:::tip 401 vs 403 — memorízalo así

  • 401: "¿Quién eres?" → falta o es inválida la credencial.
  • 403: "Sé quién eres, y no puedes." → la credencial es válida pero el permiso no. :::

5xx — Error del servidor​

CódigoNombreCuándo
500Internal Server ErrorExcepción no controlada
501Not ImplementedMétodo no implementado
502Bad GatewayUn proxy recibió una respuesta inválida del upstream
503Service UnavailableSobrecarga o mantenimiento
504Gateway TimeoutEl upstream no respondió a tiempo

6.3. Devolver códigos desde Spring Boot​

Tres formas equivalentes​

// 1. Por defecto: 200 OK
@GetMapping("/{id}")
public AlumnoDTO obtener(@PathVariable Long id) {
    return servicio.obtener(id);
}

// 2. Con la anotación @ResponseStatus
@PostMapping
@ResponseStatus(HttpStatus.CREATED)          // 201
public AlumnoDTO crear(@Valid @RequestBody AltaAlumnoRequest req) {
    return servicio.crear(req);
}

// 3. Con ResponseEntity (control total: estado + cabeceras + cuerpo)
@PostMapping
public ResponseEntity<AlumnoDTO> crear(@Valid @RequestBody AltaAlumnoRequest req) {
    AlumnoDTO dto = servicio.crear(req);
    return ResponseEntity
            .created(URI.create("/api/alumnos/" + dto.id()))
            .body(dto);
}

Errores mediante excepciones​

public class AlumnoNoEncontradoException extends RuntimeException {
    public AlumnoNoEncontradoException(Long id) {
        super("No existe el alumno con id " + id);
    }
}
public AlumnoDTO obtener(Long id) {
    return repositorio.findById(id)
            .map(AlumnoDTO::from)
            .orElseThrow(() -> new AlumnoNoEncontradoException(id));
}

Manejador global de errores​

En lugar de repetir try/catch en cada controlador, se centraliza:

@RestControllerAdvice
public class ManejadorErrores {

    @ExceptionHandler(AlumnoNoEncontradoException.class)
    public ProblemDetail noEncontrado(AlumnoNoEncontradoException ex) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(
                HttpStatus.NOT_FOUND, ex.getMessage());
        pd.setTitle("Alumno no encontrado");
        pd.setType(URI.create("https://centro.es/errores/alumno-no-encontrado"));
        return pd;
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail validacion(MethodArgumentNotValidException ex) {
        ProblemDetail pd = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST);
        pd.setTitle("Datos no válidos");
        pd.setProperty("errores", ex.getBindingResult().getFieldErrors().stream()
                .collect(Collectors.toMap(FieldError::getField,
                                          FieldError::getDefaultMessage)));
        return pd;
    }

    @ExceptionHandler(Exception.class)
    public ProblemDetail generico(Exception ex) {
        log.error("Error no controlado", ex);
        return ProblemDetail.forStatusAndDetail(
                HttpStatus.INTERNAL_SERVER_ERROR, "Error interno");
    }
}

:::info @RestControllerAdvice es POA en la práctica Este manejador intercepta el flujo normal de todos los controladores sin que ninguno de ellos sepa que existe. Ese desacoplamiento — resolver una preocupación transversal desde fuera — es precisamente la idea de la programación orientada a aspectos. :::

El formato estándar de error: RFC 9457 (Problem Details)​

Spring Boot 3 lo implementa con ProblemDetail:

{
  "type": "https://centro.es/errores/alumno-no-encontrado",
  "title": "Alumno no encontrado",
  "status": 404,
  "detail": "No existe el alumno con id 42",
  "instance": "/api/alumnos/42"
}

Se activa globalmente con:

spring.mvc.problemdetails.enabled=true

⚠️ Nunca devuelvas al cliente la traza de la excepción. Filtra el detalle técnico al log y entrega al usuario un mensaje comprensible y un identificador de incidencia.

6.4. Tabla de decisión rápida​

SituaciónCódigo
Listado devuelto correctamente200
Listado vacío200 con array vacío (no 404)
Recurso creado201 + Location
Borrado correcto204
JSON mal formado400
Campo obligatorio ausente400 o 422
Token ausente o caducado401
Rol insuficiente403
Id inexistente404
DELETE sobre un endpoint de sólo lectura405
Email ya registrado409
Se envió XML a una API sólo JSON415
Fallo de conexión con la base de datos503 o 500

⚠️ Error típico. Devolver 200 OK con un cuerpo {"error": "no encontrado"}. El cliente, las cachés y los monitores verán un éxito. El código de estado es la respuesta.
