# 6. Respuestas y códigos de estado

Cada respuesta HTTP comienza con un número de tres cifras que resume qué ha pasado. Es la primera
información que leen el cliente, los proxies, los monitores y tú mismo depurando a las dos de la
madrugada. **Devolver el código correcto es parte del contrato de tu API.**

## 6.1. Las cinco familias

| Familia | Nombre | Significado |
|---------|--------|-------------|
| **1xx** | Informativa | Petición recibida, proceso en curso |
| **2xx** | Éxito | La petición se recibió, entendió y aceptó |
| **3xx** | Redirección | Hace falta una acción adicional |
| **4xx** | Error del **cliente** | La petición es incorrecta |
| **5xx** | Error del **servidor** | La petición era válida, pero el servidor falló |

📌 **La regla que hay que interiorizar**: `4xx` = "la has liado tú (cliente)"; `5xx` = "la he liado
yo (servidor)". Devolver un `500` ante datos mal formados del usuario es un error de diseño muy
común y hace que tus alertas de producción sean ruido inútil.

## 6.2. Los códigos que realmente usarás

### 2xx — Éxito

| Código | Nombre | Cuándo |
|--------|--------|--------|
| **200** | OK | Éxito general con cuerpo de respuesta |
| **201** | Created | Recurso creado. Acompañar de `Location` |
| **202** | Accepted | Aceptado para proceso asíncrono |
| **204** | No Content | Éxito **sin** cuerpo (típico de `DELETE` y `PUT`) |
| 206 | Partial Content | Respuesta parcial (`Range`), descargas y vídeo |

### 3xx — Redirección

| Código | Nombre | Cuándo |
|--------|--------|--------|
| **301** | Moved Permanently | Cambio definitivo de URL; el cliente actualiza marcadores |
| **302** | Found | Redirección temporal (histórica, ambigua) |
| **303** | See Other | Tras un `POST`, redirige a un `GET`. Base del patrón POST/Redirect/GET |
| **304** | Not Modified | La copia en caché sigue siendo válida |
| **307** | Temporary Redirect | Como 302 pero **conserva** el método |
| **308** | Permanent Redirect | Como 301 pero **conserva** el método |

### 4xx — Error del cliente

| Código | Nombre | Cuándo |
|--------|--------|--------|
| **400** | Bad Request | Sintaxis o validación incorrecta |
| **401** | Unauthorized | **No autenticado** (nombre desafortunado) |
| **403** | Forbidden | Autenticado pero **sin permiso** |
| **404** | Not Found | El recurso no existe |
| **405** | Method Not Allowed | Método no admitido; devolver `Allow` |
| **406** | Not Acceptable | No se puede satisfacer el `Accept` |
| **409** | Conflict | Conflicto de estado (duplicado, versión obsoleta) |
| **410** | Gone | Existió y se eliminó definitivamente |
| **415** | Unsupported Media Type | `Content-Type` no soportado |
| **422** | Unprocessable Content | Sintaxis válida, semántica incorrecta |
| **429** | Too Many Requests | Límite de peticiones superado; devolver `Retry-After` |

:::tip 401 vs 403 — memorízalo así
- **401**: *"¿Quién eres?"* → falta o es inválida la credencial.
- **403**: *"Sé quién eres, y no puedes."* → la credencial es válida pero el permiso no.
:::

### 5xx — Error del servidor

| Código | Nombre | Cuándo |
|--------|--------|--------|
| **500** | Internal Server Error | Excepción no controlada |
| **501** | Not Implemented | Método no implementado |
| **502** | Bad Gateway | Un proxy recibió una respuesta inválida del *upstream* |
| **503** | Service Unavailable | Sobrecarga o mantenimiento |
| **504** | Gateway Timeout | El *upstream* no respondió a tiempo |

## 6.3. Devolver códigos desde Spring Boot

### Tres formas equivalentes

```java
// 1. Por defecto: 200 OK
@GetMapping("/{id}")
public AlumnoDTO obtener(@PathVariable Long id) {
    return servicio.obtener(id);
}

// 2. Con la anotación @ResponseStatus
@PostMapping
@ResponseStatus(HttpStatus.CREATED)          // 201
public AlumnoDTO crear(@Valid @RequestBody AltaAlumnoRequest req) {
    return servicio.crear(req);
}

// 3. Con ResponseEntity (control total: estado + cabeceras + cuerpo)
@PostMapping
public ResponseEntity<AlumnoDTO> crear(@Valid @RequestBody AltaAlumnoRequest req) {
    AlumnoDTO dto = servicio.crear(req);
    return ResponseEntity
            .created(URI.create("/api/alumnos/" + dto.id()))
            .body(dto);
}
```

### Errores mediante excepciones

```java
public class AlumnoNoEncontradoException extends RuntimeException {
    public AlumnoNoEncontradoException(Long id) {
        super("No existe el alumno con id " + id);
    }
}
```

```java
public AlumnoDTO obtener(Long id) {
    return repositorio.findById(id)
            .map(AlumnoDTO::from)
            .orElseThrow(() -> new AlumnoNoEncontradoException(id));
}
```

### Manejador global de errores

En lugar de repetir `try/catch` en cada controlador, se centraliza:

```java
@RestControllerAdvice
public class ManejadorErrores {

    @ExceptionHandler(AlumnoNoEncontradoException.class)
    public ProblemDetail noEncontrado(AlumnoNoEncontradoException ex) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(
                HttpStatus.NOT_FOUND, ex.getMessage());
        pd.setTitle("Alumno no encontrado");
        pd.setType(URI.create("https://centro.es/errores/alumno-no-encontrado"));
        return pd;
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail validacion(MethodArgumentNotValidException ex) {
        ProblemDetail pd = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST);
        pd.setTitle("Datos no válidos");
        pd.setProperty("errores", ex.getBindingResult().getFieldErrors().stream()
                .collect(Collectors.toMap(FieldError::getField,
                                          FieldError::getDefaultMessage)));
        return pd;
    }

    @ExceptionHandler(Exception.class)
    public ProblemDetail generico(Exception ex) {
        log.error("Error no controlado", ex);
        return ProblemDetail.forStatusAndDetail(
                HttpStatus.INTERNAL_SERVER_ERROR, "Error interno");
    }
}
```

:::info `@RestControllerAdvice` es POA en la práctica
Este manejador **intercepta** el flujo normal de todos los controladores sin que ninguno de ellos
sepa que existe. Ese desacoplamiento — resolver una preocupación transversal desde fuera — es
precisamente la idea de la programación orientada a aspectos.
:::

### El formato estándar de error: RFC 9457 (*Problem Details*)

Spring Boot 3 lo implementa con `ProblemDetail`:

```json
{
  "type": "https://centro.es/errores/alumno-no-encontrado",
  "title": "Alumno no encontrado",
  "status": 404,
  "detail": "No existe el alumno con id 42",
  "instance": "/api/alumnos/42"
}
```

Se activa globalmente con:

```properties
spring.mvc.problemdetails.enabled=true
```

⚠️ **Nunca** devuelvas al cliente la traza de la excepción. Filtra el detalle técnico al log y
entrega al usuario un mensaje comprensible y un identificador de incidencia.

## 6.4. Tabla de decisión rápida

| Situación | Código |
|-----------|--------|
| Listado devuelto correctamente | `200` |
| Listado vacío | `200` con array vacío (**no** `404`) |
| Recurso creado | `201` + `Location` |
| Borrado correcto | `204` |
| JSON mal formado | `400` |
| Campo obligatorio ausente | `400` o `422` |
| Token ausente o caducado | `401` |
| Rol insuficiente | `403` |
| Id inexistente | `404` |
| `DELETE` sobre un endpoint de sólo lectura | `405` |
| Email ya registrado | `409` |
| Se envió XML a una API sólo JSON | `415` |
| Fallo de conexión con la base de datos | `503` o `500` |

⚠️ **Error típico.** Devolver `200 OK` con un cuerpo `{"error": "no encontrado"}`. El cliente,
las cachés y los monitores verán un éxito. El código de estado **es** la respuesta.
