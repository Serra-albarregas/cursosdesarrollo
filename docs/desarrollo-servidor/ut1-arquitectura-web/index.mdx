# UT1 · Arquitectura web y fundamentos

Antes de escribir una sola línea de Spring Boot conviene entender **qué está pasando por debajo**.
Un framework como Spring no inventa nada nuevo: automatiza, ordena y esconde detrás de anotaciones
un conjunto de mecanismos que existen desde hace más de treinta años. Si conoces esos mecanismos,
Spring te parecerá cómodo. Si no los conoces, te parecerá magia — y la magia es imposible de depurar.

Esta unidad es, por tanto, la unidad de los cimientos.

## ¿Qué vas a aprender?

Al terminar la unidad serás capaz de:

1. Explicar el **modelo cliente-servidor** y describir el recorrido completo de una petición web.
2. Distinguir qué código se ejecuta **en el navegador** y cuál **en el servidor**, y por qué importa.
3. Describir el **protocolo HTTP**: estructura de mensajes, métodos, cabeceras, códigos de estado.
4. Razonar sobre el carácter **sin estado** de HTTP y las técnicas para simular estado
   (cookies, sesiones, tokens).
5. Identificar el papel de **servidores web, contenedores de servlets y servidores de aplicaciones**.
6. Comprender los conceptos de la **programación orientada a aspectos (POA/AOP)** y reconocer dónde
   aparece dentro de Spring.

## Requisitos previos

- Programación orientada a objetos en **Java** (clases, interfaces, herencia, genéricos básicos).
- Nociones de **HTML y CSS**; no se requiere JavaScript avanzado.
- Manejo de **línea de comandos** y de un IDE (IntelliJ IDEA o VS Code).

:::tip Herramientas recomendadas para esta unidad
- Un navegador con **DevTools** (pestaña *Network*).
- **curl** o **HTTPie** para lanzar peticiones desde terminal.
- **Postman**, **Insomnia** o la extensión *REST Client* de VS Code.
- Opcionalmente **Wireshark** para ver tráfico a bajo nivel.
:::

:::note Sobre la notación
A lo largo del curso verás bloques marcados así:

- **📌 Concepto**: definición que debes memorizar.
- **🔧 Práctica**: algo que debes ejecutar tú.
- **⚠️ Error típico**: fallo habitual que conviene anticipar.
:::
